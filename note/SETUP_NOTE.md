# ichigyo note 版：リンクから始まったクラウドの Claude への指示書

版: 2026-11-18 note v1.0（この行が無い古いファイルは使わない）

あなた（Claude）は claude.ai/code のセッションの中にいる。お客さんは、購入時に渡されたリンクを押して Enter を押しただけ。
最初の文に **合言葉** が入っている（2回目からは環境の設定 `ICHIGYO_NOTE_PASS` に入っている）。このリポジトリ（公開）の `note/` には、この指示書・鍵のかかった部品 `note_set.enc`・記録の道具 `note_state.py` だけがある。
お客さんのパソコンは使わない（ログイン情報をコピーしてもらうときだけ、お客さんのブラウザを見てもらう）。お客さんにファイルを扱わせない。**お客さん用の GitHub の置き場所は作らない（頼まない）。** 記録はお客さんの note の **下書き1本** にしまう（`note_state.py`）。
リポジトリの最上位にある `SETUP_LINK.md` などは WordPress 版、`hatena/` ははてなブログ版のもの。**note 版では読まない・使わない。**
（テスト中だけ）画面のフォルダに `note/` が無いときは、環境の設定の `ICHIGYO_KIT_REF` を使い、`git fetch -q origin "$ICHIGYO_KIT_REF" && git show FETCH_HEAD:note/SETUP_NOTE.md` でこの指示書を読む。6章の続きのリンクと9章の定期実行の指示文にも、同じ読み方を1文で足す。テスト用の開始リンク（最初の文に『テスト』と枝の名前がある）から始まったときは、R章の REF にその枝を使い、4章の設定に `ICHIGYO_KIT_REF=<その枝>` も入れる。

**note について知っておくこと**：note には公式の投稿の仕組みが無い。この道具は note の編集画面が使っている仕組みで下書きを作る。ログインは、お客さんがブラウザでログインしたときの「ログイン情報（Cookie の `_note_session_v5`）」を環境の設定 `NOTE_SESSION` に貼ってもらって使う。ログイン情報には期限があり、切れたら（`NOTE_LOGIN_EXPIRED`）貼り直してもらう（12章）。

  - 任せる作業：8章の 8-2（話し方づくり）から試し記事と 8-3 まで／10-1 の「今すぐ1本」／定期実行の新記事・リライト案・キーワード補充と報告
  - 渡す文：「【下請け】`<このリポジトリの場所>/note/SETUP_NOTE.md` の0章とR章を読み、R章を実行してから、〈やること。定期実行ならその指示文をそのまま〉。新記事は 8-3 も通す。終わりは R章の『終わり』（commit → `note_state.py push`、`STATE_SAVED`）まで必ず行う。最後に、下書きの key・タイトル・画像の枚数と今月の画像代・`STATE_SAVED` が出たか・`STATE_NEW_ID` が出たか（出たらその値）・`NOTE_LOGIN_EXPIRED` が出たか・お客さんに伝えることを、日本語10行以内で返す」
  - この画面では、返ってきた内容から、お客さんへの文（日本語・短く）だけを書く。`STATE_SAVED` が無いときや失敗したときは、そのことも1行で書く。`STATE_NEW_ID` が返ってきたら、7章の「記録の場所を覚える」をこの画面で行う。`NOTE_LOGIN_EXPIRED` なら 12章の「ログインが切れたとき」。

## 1. 部品を開ける（何も聞かずに最初にやる）
R章の手順を、合言葉を最初の文から取って実行する（`ICHIGYO_NOTE_PASS` がまだ環境に無いため）。この時点ではログイン情報が無いので、R章の 4（記録を取り出す）は飛ばす。`SET_OK` が出なければ、お客さんへ「合言葉が違うようです。購入のときに届いたメールのリンクを、もう一度押してください」とだけ書いて止まる。

## R. 毎回の準備（1章・7章・定期実行のすべての最初）
```bash
# 0. 最新の手順書と部品を、画面のフォルダを変えずに /tmp/nkit に取る（画面の枝は動かさない）
cd "$(git rev-parse --show-toplevel)" && R=/tmp/nkit && rm -rf $R && mkdir -p $R; REF=${ICHIGYO_KIT_REF:-main}; ok=1; git fetch -q origin "$REF" || ok=0; for f in SETUP_NOTE.md note_state.py note_set.enc; do [ $ok = 1 ] && { git show "FETCH_HEAD:note/$f" > "$R/$f" || ok=0; }; done; if [ $ok = 1 ]; then echo KIT_LATEST; else cp note/SETUP_NOTE.md note/note_state.py note/note_set.enc $R/; echo KIT_NOT_UPDATED; fi
PY=$(command -v python3.13 || command -v python3); $PY -m pip install -q requests pillow
rm -rf /tmp/nset && mkdir -p /tmp/nset
# 1. 合言葉：2回目からは環境の ICHIGYO_NOTE_PASS。環境に無いとき（初回）は export ICHIGYO_NOTE_PASS='<最初の文の合言葉>'（表示しない）
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in $R/note_set.enc -out /tmp/nset/set.zip -pass env:ICHIGYO_NOTE_PASS 2>/dev/null
python3 -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).extractall('/tmp/nset')" /tmp/nset/set.zip && echo SET_OK
S=/tmp/nset/ichigyo_note_SET_v1
# 2. 作業フォルダ（キットの初期状態）。お客さんごとのもの（設定・話し方・在庫）は $W/site に置く
W=/home/user/ichigyo-note-work; rm -rf $W && mkdir -p $W/ichigyo $W/site && cp -r "$S/note_auto" $W/note_auto
# 3. 手元だけの git（記録の前後を見比べるため）
cd $W && git init -q -b claude/state && printf '*.env\n*secret*\n' > .gitignore && git add -A && git commit -qm base
# 4. 記録を取り出す（ログイン情報が入ってから。NO_STATE はまだ何もしまっていないだけ）
python3 -I "$R/note_state.py" pull $W && git add -A && { git commit -qm restored -q >/dev/null 2>&1 || true; }; cat $W/ichigyo/STATE.md 2>/dev/null
# 5. このブログ用のもの（設定・話し方・在庫）を道具にかぶせる
cp -r $W/site/. $W/note_auto/ 2>/dev/null && echo OVERLAY_OK
```
- 0 で `KIT_LATEST` が出たら、**以後の手順は `/tmp/nkit/SETUP_NOTE.md`（最新）で読む**。出なければ、もう一度だけ試し、だめなら古い手順のまま進めて報告に1行。
- **画面のフォルダ（このリポジトリ）では git の操作をしない**（pull・reset・commit・push・枝づくりをしない）。もし『送っていない変更がある』という確認が出たら、`git reset -q --hard @{u} 2>/dev/null` で戻すだけにして、お客さんには何も書かない。
- 以後 `H=$W/note_auto`（道具）、`A="python3 $H/scripts/note_api.py"`（note とのやりとり）。
- **お客さんごとのものは必ず `$W/site/` に書く**（`config.json`・`prompts/system_persona.txt`・`prompts/style_site.txt`・`my_style/speech_custom.txt`・`my_style/settings.json`・`keywords_queue.csv`・`post_log.csv`・`skip_urls.txt`・`rewrite/`）。書いたら毎回 `cp -r $W/site/. $H/` でかぶせる。`$H` の中に直接書いたものは記録に残らない。
- 4 で `NOTE_LOGIN_EXPIRED` が出たら、12章の「ログインが切れたとき」へ（記事は作らない）。`FAIL state_unreadable` は1回だけやり直し、だめなら記事は作らずに報告に1行。
- 終わりは必ず：`cd $W && git add -A && git commit -qm "<何をしたか>"` → `python3 -I "$R/note_state.py" push $W`（`STATE_SAVED` が出なければ失敗として報告）。`STATE_NEW_ID <値>` が出たら、7章の「記録の場所を覚える」を行う（下請けのときは、その値を返す文に入れる）。

## 3. 最初の1通（1章が終わったらすぐ）
「ここから先は私が自動で進めます。最初に、4つだけ教えてください。

## 7. 接続の確認（新しいセッション）

- 失敗したとき（1通だけ）：
