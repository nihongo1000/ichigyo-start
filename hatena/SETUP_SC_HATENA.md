# ichigyo はてなブログ版 後付け：サーチコンソールをつなぐ → 順位を見て記事を自動で直す

版: 2026-11-19 hatena-sc v2.0（この行が無い古いファイルは使わない）

使う場面：はてなブログ版の担当の画面で、お客さんが「サーチコンソールにつないで」「サーチコンソール連携」などと送ったとき（0章から）。続きのリンクから来たときは、リンクの文の章から。
`hatena/SETUP_HATENA.md` の0章（日本語だけ・専門用語を出さない・鍵をチャットに貼らせない・合言葉を打たせない・下請けに出す）とR章（毎回の準備）が、このファイルにもそのまま効く。
**お客さんへの文に、sc-domain・プロパティ・プロジェクト ID・サービスアカウント・JSON・ファイル名・章の名前を出さない。** 画面に書いてある言葉（『次へ』『詳細』など）を押してもらうときだけ、そのまま書く。
**Google Cloud・ロボット（サービスアカウント）・鍵のファイル・Chrome の拡張機能・環境の設定画面への書き足しは、お客さんに一切頼まない。**（v1.x のやり方は使わない。お客さんがするのは、リンクを押す・Google アカウントを選ぶ・『次へ』・『コピー』・チャットに貼る・『許可』だけ。まだサーチコンソールに登録していないブログだけ、2-1 の登録が1回加わる）
以後 `G="python3 $H/scripts/gsc_fetch.py"`（サーチコンソールを読む道具。読むだけで、サーチコンソール側は何も変えない）、`L="python3 -I /tmp/hkit/sc_login.py"`（Google でログインする道具。鍵の中身は表示しない）。

## 0. 先に確かめる（聞かずに）
- R章を実行。`$W/ichigyo/STATE.md` に `DONE 8` が無ければ「先に基本の設定を終わらせましょう」と伝えて止まる。
- `STATE.md` に `SC_DONE` があれば、もうつながっている。6章の確認だけして終わる。
- 合言葉：`[ -n "$ICHIGYO_HATENA_PASS" ] && echo PASS_SET`。無ければ `SETUP_HATENA.md` 0章の合言葉の決まりのとおり（お客さんに打たせない）。
- 通信できるか（聞かずに）：`for h in oauth2.googleapis.com searchconsole.googleapis.com; do curl -s -o /dev/null -m 15 -w "$h %{http_code}\n" https://$h/; done`。どちらかが `000` か `403`（通信先に無い。v2.0 より前に作った環境）なら、先に3章の `update_environment` で通信先だけ足し（予告は3章1と同じ）、4章の形のリンクを渡す（prompt の「6章から」を「1章から」に変える）。1章以降は、その新しい画面で進める（ログイン後の文は10分ほどで使えなくなるため、通信できない画面では受け取らない）。

## 1. Google でログインしてもらう（お客さんは押して、コピーして、貼るだけ）
1. `$L url` でリンクを作る（`sc_login.py` は `ICHIGYO_HATENA_PASS` で入口の情報を開く）。
2. お客さんへ1通（〈リンク〉は1行で、そのまま）：
「サーチコンソールをつなぐと、Google での実際の順位とクリック数を見て、伸びそうな記事を選んで直せるようになります。作業は1分ほどです。
1. このリンクを押してください → 〈リンク〉
2. 『アカウントの選択』の画面が出たら、ブログをサーチコンソールに登録している Google アカウントを押してください（登録したことが無ければ、ふだん使っている Google アカウントで大丈夫です）
3. 『ichigyo.com が Google アカウントへのアクセスを求めています』と出たら、右下の白い『次へ』（または青い『続行』）を押してください（四角いチェックの欄が出ていれば、チェックを入れてから押してください）
4. もし『このアプリは Google で確認されていません』と出たら、左下の小さな『詳細』を押し、いちばん下に出る『（安全ではないページ）に移動』を押してください
5. 青い枠のページが開いたら、青い『コピー』を押してください
6. この画面に戻って、下の入力欄に貼り付けて送ってください（ichigyo-sc: で始まる文です。鍵ではないので貼って大丈夫です）」
- 『このアプリはブロックされています』『アクセスをブロック』と出た：会社や学校の Google アカウントの可能性。個人の Google アカウント（@gmail.com）で、もう一度リンクを押してもらう。

## 2. 貼られた文を鍵に換える（聞かずに）
- `$L exchange '<貼られた文>'`。`SC_LOGIN_OK` と `SITES [...]` が出る（鍵は /tmp/hkit/gsc_user.json。中身は表示しない）。
- `invalid_grant`（古い・2回使った）：1章のリンクを作り直して、2〜6 だけもう一度頼む（「もう一度だけお願いします」）。
- `SITES` からブログを選ぶ：`https://〈ブログID〉/` があればそれ、無ければ `sc-domain:〈ブログID〉`（独自ドメインのブログ）、`http://〈ブログID〉/` も同じブログとして見る。これを `GSC_SITE` にする。
- `SITES` に別のブログはあるのに、このブログが無い：「ブログを登録しているのとは別の Google アカウントを選んだかもしれません。1のリンクをもう一度押して、別のアカウントを選んでください。ほかにアカウントが無ければ『登録していない』と送ってください」。
- `SITES` が空、または『登録していない』：2-1 へ。

**2-1. まだサーチコンソールに登録していないとき**（この場合だけ、はてなの画面に1つ貼ってもらう。はてなには設定を外から変える入口が無く、Google 側の登録もお客さんの Google アカウントでしかできないため。1通・押したら『できた』）
「このブログはまだ Google のサーチコンソールに登録されていないので、先に登録します（1回だけです）。
1. このリンクを開いてください（さっきと同じ Google アカウントで）→ https://search.google.com/search-console/welcome
2. 右側の『URL プレフィックス』の欄に https://〈ブログID〉/ と入れて『続行』
3. 『所有権の確認』の画面で、『その他の確認方法』の中の『HTML タグ』を押してください
4. 出てきた1行の中の content=" と " の間の文字だけを、マウスでなぞって選び、右クリック →『コピー』（これは鍵ではありません）。ここから貼り終わるまで、ほかの物はコピーしないでください
5. このリンクを新しいタブで開いてください → https://blog.hatena.ne.jp/〈はてなID〉/〈ブログID〉/config/detail
6. 画面を下に動かして『解析ツール』の欄の『Google Search Console 認証』の枠に、右クリック →『貼り付け』→ いちばん下の『変更する』
7. サーチコンソールのタブに戻って『確認』を押してください。『所有権を確認しました』と出たら『できた』と送ってください」
- 『Google Search Console 認証』の枠が見つからないときだけ、4 で1行まるごとコピーして、同じ画面の『headに要素を追加』の枠の最後で Enter を押してから貼ってもらう（今ある行は消さない）。
- 『確認できませんでした』：6 の『変更する』が押されていない／貼った文字が途中で切れている。5〜7 をもう一度。
- 『できた』が来たら `$L sites`（ログインし直さずに一覧を見直す）で `https://〈ブログID〉/` が出ることを確かめ、`STATE.md` に `SC_PROP url`。出なければ1分おいてもう一度だけ見る。
- 登録したばかりのブログは、数字がたまるまで数日〜数週間かかる。7章の「0件」の報告はそのため。

## 3. 設定に入れる（お客さんは許可のボタンだけ）
1. 予告：「このあと『許可』の枠が出ます。中のボタン（『許可』『Approve』など）を押してください」
2. `update_environment`（〈環境の名前〉）で：
   - 設定：`GSC_SA_JSON` ＝ /tmp/hkit/gsc_user.json の中身（1行の JSON そのまま。名前は古い型と同じだが、中身は「Google でログイン」の鍵）、`GSC_SITE` ＝ 2で選んだもの
   - 通信先：`searchconsole.googleapis.com`・`oauth2.googleapis.com` が無ければ足す
   - チャットの文には中身を書かない（許可の枠に出るのは、お客さん自身の画面だけ）
3. 断られたら、もう一度は聞かない。「先ほどの枠で、ボタンを押してください」とだけ書く。
- **お客さんに環境の設定画面を開かせて、何かを書き足させることはしない。**
- `STATE.md` に `SC_STEP 3` と書いて push（R章の終わり）。

## 4. 続きのリンクを渡す
設定は、あとから始めたセッションにしか入らないので、`SETUP_HATENA.md` 6章と同じ形のリンクを作る。prompt は「ichigyo はてなブログ版の続きです。GitHub の公開リポジトリ nihongo1000/ichigyo-start を使います。/home/user/ichigyo-start に無ければ、このセッションに追加するか git clone https://github.com/nihongo1000/ichigyo-start.git /home/user/ichigyo-start で取り、ほかのリポジトリには触れないでください。その中の hatena/SETUP_SC_HATENA.md の6章から続けてください。お客さんへの文も途中経過も、すべて日本語で書いてください。合言葉: 〈合言葉〉」（`repositories=` が効かない画面もあるので、最初の文は省かない。テスト中は `SETUP_HATENA.md` 6章のテストの足し方と同じ）。
「最後に、このリンクを押して、出てきた画面で Enter を押してください。新しいタブで開きます。そこで、つながったかを確かめます。これからは、その新しい画面がこのブログの担当になります → 〈リンク〉」

## 6. 確認（新しい画面）
- 合言葉が環境に無ければ `SETUP_HATENA.md` 7章の最初と同じように入れる。R章 → `pip install -q google-auth` → `$G check`（鍵の中身は表示しない。OK と件数だけ）。
- `CHECK OK site=…`：`$W/site/config.json` に `"gsc_site": "<その site>"` を入れて `cp -r $W/site/. $H/`。`SITE.md` に `サーチコンソール: つながっている（<site>）`、`STATE.md` に `SC_DONE <日付>` と `REWRITE_AUTO off`。
- 失敗（1通だけ）：
  - `ENV_MISSING GSC_SA_JSON`／`KEY_BROKEN`：3章の `update_environment` が通っていない。3章をもう一度（許可の枠）→ 4章のリンク
  - `KEY_REJECTED`：お客さんが Google 側で許可を取り消した、または古い型の鍵。1章からやり直す（「もう一度だけお願いします」）
  - `SITE_DENIED`：`GSC_SITE` を `https://〈ブログID〉/` と `sc-domain:〈ブログID〉` で入れかえて試す（`update_environment`）。それでも同じなら、ログインした Google アカウントにそのブログの権限が無い。1章から（別のアカウントを選んでもらう）
  - 通信できない：`update_environment` で `searchconsole.googleapis.com`・`oauth2.googleapis.com` を足す
- **担当の画面の引っ越し**：`list_triggers` で前の担当の画面に結び付いた定期実行を `delete_trigger` で消し、`SETUP_HATENA.md` 9-1 と同じ回数（`STATE.md` に書いてある）で、この画面に作り直す。リライトの予約が無かった（9-0 で『しない』）なら、週1回のリライトを足す（新記事と違う曜日・時刻）。`set_session_title` でこの画面の名前を「〈環境の名前〉 担当（消さないでください）」にする。
- push（R章の終わり）。お客さんへ：
  「サーチコンソールがつながりました。これからは週に1回、Google での順位とクリックを見て、伸びそうな記事を1本選んで直します。はじめの2本は、直す前に案だけをお送りします（『反映して』と送ってもらえたら直します）。その後は、ご希望があれば自動で直すように切りかえます。前の画面は閉じて大丈夫です。これからはこの画面が担当です」

## 7. 自動で直す仕組み（定期実行のリライト。`SC_DONE` があるときは `SETUP_HATENA.md` 12章のリライト案の代わりにこれを使う）
下請けに出す（`SETUP_HATENA.md` 0章）。渡す文は「【下請け】… R章を実行してから、`hatena/SETUP_SC_HATENA.md` の7章を行う …」。

**7-1. 数字を読む（毎回）**
- `pip install -q google-auth` → `$G check`。`CHECK OK` でなければ、報告に「サーチコンソールが読めませんでした」と1行書き、`SETUP_HATENA.md` 12章のリライト案（ラッコ／古い順）で1本だけ案を作って終わる（直さない）。2回続いたら、報告に「つなぎ直しが要るかもしれません。この画面で『サーチコンソールをつなぎ直して』と送ってください」を足す（そのときは 6章の失敗の表から始める）。
- `$G cannibal /tmp/sc3.json /tmp/sc3.md`（7日・28日・90日、カニバリ）と `$G candidates /tmp/cand.json`（候補）。
- 7日だけの変化は様子見。28日と90日でも同じなら手を打つ。

**7-2. 直した記事の見直し（28日たったもの）**
- `$W/site/rewrite_log.csv`（`date,entry_id,url,action,clicks28_before,clicks28_after,memo`）で、直してから28日以上たち `clicks28_after` が空の行ごとに `$G clicks <url> 28` を見て書き入れる。
- 前の28日より30%以上減っていたら（前が5クリック以上のときだけ）、報告に1行「〈タイトル〉は直したあと、クリックが〇→〇に減りました。元に戻すときは『〈タイトル〉を元に戻して』と送ってください」。戻すのは `$W/site/backup/<ID>_<日付>.md` を `$A put <ID> <そのファイル> --allow-public`。

**7-3. 1本選ぶ（1回1本）**
- 対象：`$A list /tmp/pub --n 100` の公開記事のうち、公開から60日以上・前のリライトから60日以上（候補の道具が自動で外す）・`skip_urls.txt` に無い・記録の下書きでないもの。URL で候補と結びつける（`list` の行の最後が URL）。
- 選ぶ順：`click_drop`（クリック減）→ `near_top`（7〜30位で表示が多い。あと一押し）→ `low_ctr`（7位以内なのにクリック率2%未満：**タイトル案だけ。本文は直さない**）。
- 0件なら「今週は直す記事がありませんでした（記事が Google に表示されはじめるまで、数か月かかることがあります）」と報告して終わる。
- `$G queries <URL>`：その記事のクエリに、自分の別の記事が出ていないか（`other_urls`）。出ていれば、その記事は直さず、次の候補へ。報告に1行「〈記事A〉と〈記事B〉が同じ言葉で競っています」（統合や削除はお客さんが決める。勝手にしない）。

**7-4. 直す**
- `$A get <ID> $W/site/backup/<ID>_<日付>.md`（直す前の控え。`backup/` は新しい5つだけ残し、古いものは消す）→ それを `$W/site/rewrite/<ID>.md` に写して直す。
- 直し方（打ち手は1つ）：`near_top` のクエリ（7〜30位）で検索する人が知りたいのに本文に無いことを、段落・H3・表・よくある質問で足す／古い情報を新しくする。`click_drop` は WebSearch でその言葉の今の上位の見出しを見て、足りないものを足す。
- 守ること：既存の見出しの本数・順番を変えない。`[f:id:〜:image]` の行は動かさない（変えると `put` が断る）。筆者の話し方・体験談を消さない（日本語ルール4章）。出典 URL を入れない。見出しに例え話・体験談を立てない。**タイトルは自動では変えない**（1行目の `<!-- タイトル -->` はそのまま）。
- `$A strip` → `python3 $H/scripts/style_check.py` → FAIL は段落の文だけ言い直す（最大2周）→ `score_article.py`。
- 直す前の28日のクリック：`$G clicks <URL> 28`。

**7-5. 反映するか（承認期間）**
- `STATE.md` が `REWRITE_AUTO off`（はじめ）：**反映しない。** 報告に、直す所の要点（3〜5行）と「反映するときは、この画面で『反映して』と送ってください」。お客さんが『反映して』と送ったら `$A put <ID> $W/site/rewrite/<ID>.md --allow-public` で直し、`rewrite_log.csv` に1行（`action=append` など）。
- 『反映して』で直したものが2本になったら、次の報告の最後に1回だけ：「次からは、案を待たずに自動で直してもよいですか。よければ『自動でOK』と送ってください（直したあとクリックが減ったら、お知らせして元に戻せます）」。
- お客さんが『自動でOK』（または「自動で直して」）と送ったら `REWRITE_AUTO on <日付>`。『案だけでいい』『自動はやめて』なら `REWRITE_AUTO off` に戻す。
- `REWRITE_AUTO on`：7-4 のあと、そのまま `$A put <ID> $W/site/rewrite/<ID>.md --allow-public` で反映し、`rewrite_log.csv` に1行。報告：「〈タイトル〉に、〈足したことを1行〉を足しました。元に戻すときは『〈タイトル〉を元に戻して』と送ってください」。
- `low_ctr` のタイトル案は、`REWRITE_AUTO` に関係なく案だけ。お客さんが『タイトルを変えて』と送ったら、1行目の `<!-- -->` だけ変えて `put`。

**7-6. 登録されていない記事（月に1回、第1週のリライトのときだけ）**
- `$A list /tmp/pub --n 100` の URL のうち、公開から14日以上のものを `/tmp/urls.txt` に書き、`$G inspect /tmp/urls.txt /tmp/inspect.md`。
- 『クロール済み - インデックス未登録』『検出 - インデックス未登録』の記事を、報告に3本まで：「〈タイトル〉がまだ Google に載っていません」＋打ち手の案1行（近いテーマの記事からリンクを足す／冒頭で答えを言う形に直す）。直すのは、お客さんが『直して』と送ってから。

**7-7. 終わり**
- `$W/site/` に `rewrite/`・`backup/`・`rewrite_log.csv` が入っていることを確かめ、R章の終わり（commit → `hatena_state.py push`、`STATE_SAVED`）。
- 報告は日本語で5行以内。数字は「先月より〇クリック増えました」程度にし、表・URL・クエリの一覧は出さない。
